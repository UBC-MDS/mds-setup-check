## The three known limitations

**1. A notebook containing a markdown table cannot be exported to PDF from
JupyterLab.** nbconvert's LaTeX template writes `\LTcaptype{none}`, which TeX Live
rejects, and *no file is produced at all*. Render the same notebook through Quarto and
it works, table and all. That is why `check-notebook-table.ipynb` is a fixture of its
own: three routes over one construct show the fault is nbconvert's LaTeX template, not
LaTeX and not notebooks.

**2. LaTeX drops literal Greek and emoji, silently, and still exits 0.** Write Greek as
maths (`$\alpha$`) and it works everywhere. Emoji have no maths form, so a document
that needs them wants Typst, HTML or WebPDF.

**3. `nbconvert -> WebPDF` does not work on Windows.** Not a Windows bug and not a
playwright bug: nbconvert's command line sets `WindowsSelectorEventLoopPolicy`, and a
`SelectorEventLoop` cannot start a subprocess, so launching Chromium raises
`NotImplementedError`. The `nbconvert API` row beside it is the same exporter called
directly, and it is green on Windows -- but JupyterLab's export menu goes through
`jupyter_server`, which sets the same policy, so students still cannot use it there.
Tell them to use Typst.

Limitations 1 and 3 kill the render outright, so they live in `KNOWN_TO_FAIL` in
`ci/assert-renders.py` with their cause; limitation 2 is a per-route expectation in the
same file. Either way, a route that *starts* working fails the build rather than being
absorbed quietly.
